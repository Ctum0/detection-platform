# Wazuh detections

Single file: `custom_rules.xml`, 14 rules.

- 100001-100012: Sigma-derived. First generated by
  `../../platform/converters/sigma_to_wazuh.py`, then hand-reviewed against
  the live Wazuh 4.14.8 ruleset. Several carry hand-tuning that differs from
  what the converter would emit (see `../../platform/converters/README.md`).
- 100013, 100020: hand-written level-0 suppression rules (no Sigma source).

The file has no header comment (the Wazuh 4.14 API rejects comments that
contain escaped entities such as `&gt;`), and no comments at all. The rule-to-Sigma mapping is in
`DEPLOY-NOTES.md` and, machine-readable, in
`../../platform/converters/wazuh_rule_ids.json`.

Do not write converter output over this file. New Sigma rules are added by
`merge_wazuh_rules.py` (run by `.github/workflows/convert-deploy.yml`), which
matches rules by Sigma identity, keeps existing rules as they are and
appends new ones with the next free ID. It never updates an existing rule
when its Sigma source changes: it prints a DRIFT report (a CI warning) and
leaves the live rule alone, so differences have to be reconciled by hand.
